# 无线方案选型

选型不是比较"哪个更省电"，而是在给定数据率和使用模式下，比较**完成同一件事所消耗的能量**，同时满足峰值电流、距离和对端设备的约束。

下面的数值是典型量级，用于方向判断；具体器件以 datasheet 为准，新器件请先查最新资料。

## 1. 先算需要多少带宽

```
原始数据率 = 采样率 × 位宽 × 通道数
应用层需求 = 原始数据率 × (1 + 协议开销) ÷ 压缩比
选型要求：方案的实际应用层吞吐 ≥ 需求 × 2（留一倍余量给重传、干扰和手机端限制）
```

例：
- 6 轴 IMU，16 bit，100 Hz：6 × 16 × 100 = 9.6 kbps → BLE 轻松满足。
- 6 轴 IMU，16 bit，1 kHz：96 kbps → BLE 1M PHY 可以，建议开启数据长度扩展(DLE)。
- 单声道音频 16 kHz / 16 bit PCM：256 kbps → BLE 2M PHY 勉强且费电，应先压缩（如 ADPCM、Opus、LC3）到几十 kbps。
- 8 通道 24 bit 生理信号 2 kHz：384 kbps → BLE 2M PHY 接近极限，考虑本地降采样、存储后批量传或 WiFi。
- 图像/视频：WiFi。

如果数据不需要实时，可以本地缓存后批量传输，这时关心的是总能量而不是瞬时吞吐。

## 3. 选型逻辑

**能量视角**：WiFi 每比特能量其实可以很低，因为速率高；它的问题是固定开销大——每次唤醒、关联、拿地址、建立加密连接要消耗数秒的百 mA 级电流。因此：

- 少量数据、频繁上报、连接手机 → BLE。
- 大量数据、偶尔上传、有路由器 → WiFi 批量上传，其余时间彻底关断射频；或 BLE 负责控制与小数据、WiFi 负责批量传输。
- 需要常在线且直接上云、又要电池供电 → 评估 WiFi 的 DTIM/TWT 休眠功耗是否在预算内，通常需要几百 mAh 以上的可充电池。
- 很多节点、家庭/楼宇、需要 IP 与互通 → Thread（Matter）。
- 距离远、数据极少 → LoRaWAN 或蜂窝 LPWAN。

**峰值电流视角**：峰值决定电池和电源设计。选了 WiFi 或蜂窝，就等于选了锂电池、数百 mA 能力的稳压器和足够的储能电容；纽扣电池方案只能配 BLE / 802.15.4 这类 mA 级峰值的射频。

**对端视角**：要连手机，实际只有 BLE（以及 WiFi 和 NFC）。iOS 与 Android 会限制连接间隔、MTU 和 PHY，实际吞吐以目标手机实测为准。

**其它需要与用户确认的点**
- 是否需要定位或测距（BLE 信道探测、UWB、GNSS）。GNSS 是功耗大户，需要单独做占空比设计和电源开关。
- 是否需要 NFC 做配对、唤醒或无电池读取。
- 共存：同一设备上 BLE 与 WiFi 同在 2.4 GHz，需要共存机制和天线隔离。
- 发射功率：提高发射功率换距离的代价是峰值电流；先优化天线效率和接收灵敏度（如 Coded PHY），通常比加 PA 划算。

## 4. BLE 的参数与功耗

BLE 的平均电流几乎完全由"多久醒一次、每次醒多久"决定：

- **广播间隔**：20 ms 至 10.24 s。1 s 间隔的不可连接广播平均电流在十几 µA 量级；100 ms 间隔约为其十倍。
- **连接间隔**：7.5 ms 至 4 s。间隔越长越省电但延迟和吞吐越差。
- **外设延迟(peripheral latency)**：允许外设在没有数据时跳过若干连接事件，是兼顾低延迟与低功耗的主要手段。
- **PHY**：2M PHY 空中时间减半，传同样数据更省电但灵敏度略差；Coded PHY 距离远但空中时间是 1M 的 2 倍或 8 倍。
- **发射功率**：0 dBm 与 +8 dBm 的峰值电流可相差一倍以上。
- **睡眠时钟精度**：低频时钟越不准，接收窗口要开得越宽，平均电流越高。使用 32.768 kHz 晶体（±20 ppm）比内部 RC 更省电，长连接间隔下差别明显。

## 5. 模组还是芯片直贴

| | 认证模组 | 芯片直贴 |
|---|---|---|
| 射频设计 | 已完成，含天线或天线接口 | 需自行设计匹配与天线，需要网络分析仪调试 |
| 认证 | 多数地区可沿用模组认证（需遵守其天线和布局条件） | 自行完成全部射频认证 |
| 成本 | 单价较高 | 单价低，前期投入高 |
| 尺寸 | 较大 | 可做到最小 |
| 适用 | 小批量、团队射频经验少、赶时间 | 大批量、尺寸极限、有射频能力 |

使用模组时仍需遵守其硬件设计指南：天线端伸出板边或下方净空、周围金属和地的距离、电源去耦。改用非原配天线可能需要重新认证。

## 6. 输出给用户的选型结论应包含

1. 计算出的数据率需求与余量。
2. 推荐方案及备选，各自的吞吐、距离、峰值电流、估算的平均电流。
3. 该方案对电池、电源、天线、认证提出的要求。
4. 需要用户确认或实测的假设（手机型号、使用环境、距离）。
