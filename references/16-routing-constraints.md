# 布线约束、质量评分与布线插件

八方向几何、线宽、线长、过孔、间距、层的量化约束，布线质量评分 VF-16…27，以及检查器 `route_lint.py`、修复器 `route_fix.py` 的用法。适用于低功耗 IoT 常见的 2 层、4 层板（≤ 50 MHz 数字、BLE / Wi-Fi 2.4 GHz、USB 2.0、小功率 DC-DC）。

一句话：**DRC 只保证合法，这里保证有序**。任意角度斜线、锐角、锯齿、斜着出焊盘、散乱过孔、底层乱穿切碎地，都来自同一个原因：把飞线直接当铜皮画出来（“飞线物化”），既没有角度约束，也没有后处理和通道规划。对策是让几何由确定性代码生成和把关，写入 EDA 前过一道只许 0/45/90/135° 的闸门。

## 1. 何时用

- 布线前：生成约束文件和 KiCad 规则（第 6、7 节），定网络类、层角色、过孔预算。
- Claude 通过 EDA 工具落线时：先确认设计闸门 G0–G4 已放行（`19-design-gate.md`，`gate` 和 `route_fix.py` 都要带 `--brief design-brief.json`，未放行退出码 3）；**每一批线段写入前**跑 `route_lint.py gate`；写完回读跑 `lint`（第 8 节）。
- 用户发来截图或板文件说“走线很乱”：跑 `lint` 出报告，再跑 `route_fix.py` 自动修几何问题，修不了的逐条讲清原因。
- 布线后评审：评分并入验证器阶段 R（`13-layout-verifier.md` 的 VF-16…27），写进 Layout 评审报告。

与其他文件的分工：`14-routing-practice.md` 讲布线顺序、升级阶梯和自动布线器；`15-design-rules-and-process.md` 讲板厂下限与价格档位；`07-layout.md` 讲布局与走线复核；本文件讲**走线本身的几何与质量**；`17-routing-principles.md` 讲布线优先级、就近、差分、隔离这些决策原则和对应的检查。

## 2. 烂走线的成因

| 现象 | 机制 | 对策 |
|---|---|---|
| 任意斜率的长斜线，彼此不平行 | 以焊盘中心为端点直接画直线（飞线物化），没有方向集合约束和栅格 | 写入闸门 RTG-01；修复器用肘形 / 三段式 / 八方向 A* 重建 |
| 锐角拐角、V 形尖角、锐角 T 分支 | 逐段贪心，每段只朝下一个点走，拐角不计代价、分支不查角度 | RTG-02/03；搜索状态带方向，锐角转向代价为无穷大 |
| 锯齿、抖动、短段、平行线间距不一 | 栅格过细且拐弯无代价，推挤后不做优化，每根线各布各的 | RTG-05/06，拐弯代价，共线合并、去微折，成束布线 |
| 细线在空白处长距离斜穿，把地切碎；过孔散乱 | 没有层方向分配，底层被当成第二信号层；过孔不计代价 | 层主方向 RTY-02/03，过孔代价与预算 RTV-01，地破碎度 VF-21 |
| 没有通道和总线规划 | 只有详细布线，没有全局布线，布局时不考虑逃逸方向 | 先规划通道再落线；拥塞时回到布局 |

学术界的布线基准（CADET、PCBWorld）只奖励连通、零 DRC、线长和过孔数，没有任何“整齐度”项，所以照着它们做的流程会产出“合法但难看”的走线。本文件把整齐度写成了硬约束和评分项。

## 3. 原则与出处

- **拐角的电气影响很小，禁 45° 以外角度是为了可制造、可检查和密度**。Bogatin 的经验式：线宽（mil）大于 5 × 上升时间（ps）才需要担心拐角；Brooks 用 17 ps 上升时间的 TDR 测不出 45° 或 90° 拐角的反射。“酸阱”对 90° 基本过时，但对**锐角**楔形仍是真实风险，所以锐角一律禁止。
- **间距看到参考平面的高度 h，不看线宽**。3W 只在 W ≈ h 时成立；2 层 1.6 mm 板 h ≈ 1.5 mm，3W 远远不够，有效的办法是底层完整地或做 4 层板（LearnEMC）。
- **电流走回路**。DC-DC 热回路面积最小、开关节点铜面积最小（TI SLUP432）；信号换层时 200 mil 内放回流地过孔（TI SPRAAR7）。
- **厂商硬要求**。ESP32-C3：4 层时 L2 完整地不走线，射频线 50 Ω 等宽不分叉、不打过孔、拐弯用 135° 或圆弧，晶振线不打过孔，主电源 ≥ 25 mil，芯片底部地焊盘 ≥ 9 个过孔。nRF52：射频复制参考设计，射频路径下方不走线，地焊盘旁各一个过孔，大面积地每 5 mm 一个过孔，中心焊盘至少 3×3 过孔。ST AN2867：晶振贴近 MCU，地保护环。USB 2.0：差分 90 Ω ±15%，对内长度差 ≤ 1.25 mm，桩线尽量短。
- **工具界的标杆把任意角度当例外**。KiCad 推挤布线器给拐角打分：直通 5、45° 转向 10、直角 30、锐角 50、回折 60、其他 100；“自由角度模式”只在特定模式下可用。TopoR 一类的任意角度布线是拓扑规划的副产品，交付前应八方向化（射频、柔性、高压豁免区除外）。

## 4. 约束表

依据等级：**[S]** 标准或厂商要求，**[C]** 业界共识，**[E]** 经验值（按项目改）。严重度：**P0** 阻断交付；**P1** 签核前必须修或书面豁免；**P2** 质量与可维护性；**P3** 外观。“自动”一列：✓ 表示 `route_lint.py` 会检查，✎ 表示修复器会处理，空白表示靠人工或 DRC。

| RTW-02 | PWR_LOW（≤ 0.3 A） | 0.30 | 0.25 | ESP32：非主电源 10 mil | P1 | ✓ |

### 4.3 线长（RTL）

八方向最短距离 d_oct = max(|dx|, |dy|) + (√2 − 1)·min(|dx|, |dy|)；绕行率 τ = 走线长度 / d_oct，多端网用八方向最小生成树长度做分母。

| 编号 | 内容 | 默认值 | 严重度 | 自动 | 依据 |
|---|---|---|---|---|---|
| RTL-01 | 普通网络绕行率 | τ ≤ 1.3；d_oct < 5 mm 时 τ ≤ 1.6 | P2 | ✓ | [E]，与 VF-15 一致 |
| RTL-02 | 关键网络绕行率（时钟、晶振、射频、USB、模拟） | τ ≤ 1.15 | P1 | ✓ | [E] |
| RTL-03 | 晶振走线 | 每根 ≤ 5 mm，0 过孔，晶振下方不走其他信号 | P1（有过孔 P0，见 RTV-01） | ✓ 长度 | [S] Espressif、ST |
| RTL-04 | 去耦电容 | 走线 ≤ 2 mm（0402/0201 力争 ≤ 1 mm）；电源 → 电容焊盘 → 引脚；地过孔距焊盘 ≤ 0.5 mm | P1 | | [S] Nordic |
| RTL-05 | DC-DC 热回路 | 输入电容紧贴 VIN/PGND，同层闭合不经过孔，≤ 3 mm | P1 | | [S] TI |
| RTL-06 | 射频馈线 | 尽量短，0 过孔，不分叉 | P0 | ✓ 分叉 | [S] Espressif |

## 5. 质量评分 VF-16…27

满分 100（各项扣分按全部权重归一化：本表 11 项加 `17-routing-principles.md` 的 VF-28…30，共 122），**任一 P0 即“不通过”**，与分数无关。每项按下表扣分，单项不超过权重。DRC（间距、短路、开路）是前置闸门，不计分。阈值是本方案提出的经验值，用黄金样例（官方参考布局、人工精布的板子）标定后再固化。

| 编号 | 指标 | 定义 | 良好 → 不合格 | 权重 |
|---|---|---|---|---|
| VF-16 | 任意角度 | 非豁免区非八方向线段数（含 RTG-10） | 0 → 每处扣 40% 起，递增 | 15 |
| VF-17 | 锐角 | 锐角拐角 + 锐角 T 分支数 | 0 → 每处扣 40% 起，递增 | 10 |
| VF-18 | 短段、抖动与出线 | （短段 + 抖动 + 斜出焊盘 + 线宽突变 + 悬空线头）/ 每 100 段 | ≤ 1 → ≥ 4 | 8 |
| VF-19 | 多余拐弯 | 每段连接的转角和（45° 记 0.5，90° 记 1）减去连接本身必需的转角，取平均 | ≤ 0.5 → ≥ 2 | 8 |
| VF-20 | 过孔 | 超预算网络数 + 盘中孔 | 0 → > 2 | 10 |
| VF-21 | 地平面完整性 | 该当地平面的层（2 层板底层、4 层板内层）的最大破碎度；内层地上走线直接满扣 | ≤ 0.05 → ≥ 0.15 | 12 |
| VF-22 | 绕行率 | 普通网 τ 的 P90；关键网 τ 的最大值 | ≤ 1.2 且 ≤ 1.1 → ≥ 1.4 或 ≥ 1.2 | 8 |
| VF-23 | 成束整齐度 | 束内间距标准差（或与 pitch 的偏差） | ≤ 0.02 → ≥ 0.08 mm | 7 |
| VF-24 | 层方向与层使用 | 逆主方向占比；2 层板底层跳线（RTL-11） | ≤ 15% → ≥ 35% | 6 |
| VF-25 | 走线密度 | 2.5 mm 瓦片铜占用率的变异系数，及占用 > 60% 的瓦片 | CV ≤ 0.8 → ≥ 1.6 | 6 |
| VF-26 | 网络类约束 | 线宽下限、晶振长度、射频分叉、USB 长度差与过孔成对、换层回流过孔 | 全部合规 → 有 P0 或 > 2 个 P1 | 10 |
| VF-27 | 总分 | 100 × (1 − 扣分合计 / 权重合计)；验证器在 < 75 时给出总分结论 | ≥ 90 优秀，≥ 75 合格，≥ 60 需返工 | — |

测试板 `tests/fixtures/route-good.kicad_pcb` 得分约 99，`route-bad.kicad_pcb` 约 61；修复后约 93（剩下的是晶振过孔和底层长跳线，属于拓扑问题，要人决定）。差分、就近、优先级与隔离的评分（VF-28…30）见 `17-routing-principles.md` 第 7 节。

## 6. 工具

### 6.1 检查与评分：`route_lint.py`

```bash
python scripts/route_lint.py lint board.kicad_pcb [--constraints c.json] [-o report.md] [--json report.json]
python scripts/route_lint.py lint copper-pack.json            # extract_copper.py 的数据包也可以
```

报告给出得分、等级、11 项指标和逐条违规（规则、网络、层、位置、说明）。位置 `at_src` 是板文件坐标（KiCad 为 y 向下），`at` 是数据包坐标（左下角为原点、y 向上），可直接在验证器里定位。有 P0 时退出码为 1。

`extract_copper.py` 生成数据包时会自动跑一遍检查，结果放在 `checks.routing`，验证器阶段 R 显示为 VF-16…27（见 `13-layout-verifier.md`）。

### 6.2 自动修复：`route_fix.py`

```bash
python scripts/route_fix.py board.kicad_pcb --brief design-brief.json [-o fixed.kicad_pcb] [--diff diff.json] [--constraints c.json] [--clearance 0.15] [--no-chamfer]
```

修复顺序：合并重叠的共线线段 → 删除悬空线头 → 逐段重建有问题的走线 → 信号线 90° 斜切 → 再查一遍（最多两轮）。

- **修复单位**是两个锚点之间的一段走线。锚点是焊盘、过孔、分支点和线宽变化点，坐标不动。
- **候选**依次是直线、两种肘形（先斜后直 / 先直后斜）、两种三段式（直-斜-直 / 斜-直-斜）；焊盘端可先沿允许的轴直出到焊盘外 max(0.2 mm, w)。按代价排序（长度、斜行 1.1 倍、45° 转向 +1、90° 转向 +3、短段 +2），取第一个合法的。
- **都不合法**时，在“原路径包围盒 + 2 mm”的窗口里跑八方向 A*（状态含方向，锐角和回折不展开，障碍按 w/2 + 间距膨胀后栅格化）。
- **提交前的闸门**：只有八方向线段、没有锐角、出焊盘正确；与其他网络的走线、焊盘、过孔的间距不小于规则，不出板框、不进禁布区；整个网络的连通关系不变。任一条不满足就保留原样，记为 `needs_manual`。
- **不改的东西**：圆弧、GND 网络、约束里 `locks` 列出的网络、拓扑（过孔数、层、连接关系）。
- **写回**：只删改变化的 `(segment …)`，其余文本原样保留；新线段沿用文件里的 uuid 或 tstamp 写法。修复后在 KiCad 里按 B 重新填充铺铜，再跑 DRC 和 `lint`。
- 修复是幂等的：对修过的板再跑一次不会有任何改动。

### 6.3 约束文件：`constraints`

```bash
python scripts/route_lint.py constraints board.kicad_pcb --layers 4 -o constraints.json --dru routing.kicad_dru
```

生成 `lpiot-routing/1.0` 约束文件（结构见 `assets/routing/constraints.schema.json`，示例见 `assets/routing/constraints-example.json`）：

- `layers`：层角色与主方向。2 层板顶层双向、底层是地（只许跳线）；4 层板 L2 地（禁止走线）、L3 电源、L1 沿板长轴、L4 沿短轴。
- `netclasses`：各网络类的线宽、最小线宽、过孔预算、绕行率上限等（第 4 节的默认值），可按项目覆盖。
- `nets`：每个网络的类别和置信度；`confirm` 列出置信度 < 0.8、需要人确认的网络。推导规则：网络名正则（GND、SW/LX、USB D±、XTAL、ANT/RF、VBAT/VBUS、VDD/+3V3、CLK/SCK、ADC/SENS、SCL/SDA…），再看拓扑（连到晶振 → XTAL，连到 USB 连接器 A6/A7/B6/B7 → USB90，连到天线 → RF50，电感与芯片之间 → SW）；名字含 RF 但像控制线（EN/CTRL/SEL）的归为普通信号。
- `bundles`（成束网络与间距）、`exempt_zones`（豁免区，写明 `rules` 和 `reason`）、`keepouts`（禁布区）、`locks`（修复器不改的网络）需要手工补。

### 6.4 写入 EDA 前的闸门：`gate` 与 `plan.json`

Claude 通过嘉立创 EDA 扩展 API 或 KiCad 写线段时，先把这一批线段写成 `plan.json`，过闸门：

```json
{"units": "mil", "ydown": true, "layers": ["TOP", "BOTTOM"],
 "pads": [{"ref": "U1", "pin": "1", "layer": "TOP", "x": 0, "y": 0, "w": 12, "h": 40, "rot": 0, "net": "SDA"}],
 "segs": [["TOP", 0, 0, 600, -350, 8, "SDA"]],
 "vias": [[x, y, 直径, "网络"]],
 "outline": [[x, y], ...]}
```

```bash
python scripts/route_lint.py gate plan.json --brief design-brief.json          # 有任意角度、锐角、锐角分支 → 退出码 1，打印位置
python scripts/route_fix.py plan.json --brief design-brief.json -o plan-fixed.json
python scripts/route_lint.py gate plan-fixed.json --brief design-brief.json    # 通过后才调用 EDA 写入
```

`units` 为 `mm` 或 `mil`；`ydown` 表示坐标 y 向下；`pads` 只需要这批线段两端的焊盘（用来检查出线方向），`w`、`h` 是焊盘尺寸，`rot` 是焊盘角度。闸门打印的位置单位是 mm、y 向上。

### 6.5 测试与示例板

`tests/fixtures/make_route_fixtures.py` 生成一对 2 层测试板：好板全部八方向、沿焊盘长轴出线、底层整层地；坏板注入任意角度、锐角拐角、锐角 T 分支（含残桩）、Z 形抖动、斜着出焊盘、底层长斜跳线、晶振线打过孔、重叠折回。`tests/test_routing.py` 断言好板 ≥ 90、坏板 ≤ 60、修复后 VF-16/17 为 0、连通不变、间距不变差、幂等、文件往返，并对 200 条随机折线做性质测试。

## 7. KiCad 规则与生效自检

`python scripts/fab_rules.py emit --layers N -o 输出目录` 除板厂下限 `fab.kicad_dru` 外，还生成 `routing.kicad_dru`：

- `track_angle (min 90deg)`：禁止锐角拐角（RTG-02）；
- `track_segment_length (min 0.15mm)`：最小线段长度（RTG-05）；
- 预算为 0 的网络类 `via_count (max 0)`（XTAL、RF50）；
- 各网络类最小线宽（不低于板厂下限）。

合并时把 `routing.kicad_dru` 里的规则（不含 `(version 1)`）贴到自定义规则末尾；条件里的网络类名要和板子的网络类一致（SIG、XTAL、RF50…），不一致就改条件。

**必须自检**：`track_angle` 的角度定义（相邻两段的夹角，180° 为直通）和单位写法在 KiCad 9、10 之间有差异，有项目报告过某些写法会让整个规则文件被静默忽略。第一次使用时：

```bash
python tests/fixtures/make_route_fixtures.py /tmp/rt
# 把 routing.kicad_dru 改名为 route-bad.kicad_dru 放在板子旁边，再跑
kicad-cli pcb drc --format json -o drc.json /tmp/rt/route-bad.kicad_pcb
```

确认报告里有锐角和短线段的违规；没有就说明规则没生效，按 KiCad 当前版本的“自定义规则”帮助调整写法。任意角度、抖动、出焊盘方向 KiCad 规则表达不了，始终以 `route_lint.py` 为准。

## 8. 给 AI 的布线规程

**落线前检查**（任一项为“否”就不开始）：

1. 板厂档位、叠层、阻抗线宽已由 `fab_rules.py` 给出，规则已填进 EDA（KiCad 已做第 7 节自检）。
2. 约束文件已生成，`confirm` 里的网络类已和用户确认。
3. 射频、晶振、DC-DC、USB 的布局符合厂商参考设计，逃逸方向朝向目标（`07-layout.md`）。
4. 关键网络（射频、晶振、开关热回路、USB、大电流）已手工布好并锁定，写进 `locks`。
5. 2 层板：底层是整层地；4 层板：L2 地层不走线。

**布线顺序**：按 `17-routing-principles.md` 第 2 节的档位（射频 → 晶振 → 开关回路与高压 → 高速差分 → 时钟 → 模拟 → 电源 → 一般信号 → 地），`route_lint.py order` 直接给出逐网顺序；差分对按该文件第 4 节两根一起布。

**每个网络**：读约束 → 选层与通道 → 从焊盘沿长轴直出 → 八方向折线（优先两段肘形，拐弯越少越好） → 写成 `plan.json` 过 `gate` → 不通过就 `route_fix.py` → 再过 `gate` → 写入 EDA → 回读跑 DRC 与 `lint` → 提交。线段坐标必须由八方向构造算出来（起点加上 (±d, 0)、(0, ±d)、(±d, ±d) 这类位移），不能凭感觉写两端坐标。

**升级阶梯**（同 `14-routing-practice.md` 第 5 节）：同层绕行 → 推挤 → 加中间点 → 换层（同时打回流地过孔）→ 拆低优先级网络重布 → 回到布局。

**必须回到布局**：关键网络 τ > 1.15 或需要过孔才能连通；某网络过孔超预算 2 个以上；2 层板底层地破碎度 > 0.10 且消除不了；同一区域反复拥塞、拆线三轮不收敛。

**禁止**：

- 凭两端焊盘坐标直接画一条线（飞线物化）；
- 写入非八方向线段（豁免区除外）；
- 在 4 层板地层上走线；在晶振、射频线上打过孔；换层不配回流过孔；
- 为了让 DRC 归零把线宽、间距降到网络类下限以下；
- 绕过 P0 交付；豁免不写理由。

## 9. 布线插件的架构与实现状态

```
L0 约束生成  （确定性）网络类推导 + fab_rules.py + 叠层 → constraints.json / .kicad_dru         已实现
L1 意图规划  （LLM）   优先级、关键网策略、通道 / 束 / 层分配草案，只用瓦片坐标和意图          规程（第 8 节）
L2 全局布线  （确定性）瓦片拥塞图 + 协商拥塞 → 每网走廊                                     未实现（M6）
L3 详细布线  （确定性）走廊内八方向 A* + 成束车道 + 拆线重布                                 局部 A* 已在修复器里，整网布线未实现（M5）
L4 后处理    （确定性）合并 / 去残桩 / 肘形与三段式重建 / 局部 A* / 斜切 / 不变量闸门           已实现（route_fix.py）
L5 检查评分  （确定性）RTG / RTW / RTL / RTV / RTS / RTY + VF-16…27                           已实现（route_lint.py、验证器）
L6 落线适配  （确定性）EDA 写入前闸门 → 写入 → 回读复检                                      闸门与 plan.json 已实现，EDA 适配器未实现（M7）
```

**分工**：能写成“几何 → 几何 / 数值”的都交给确定性代码（栅格、角度、路径搜索、DRC、评分、单位换算）；LLM 负责推断设计意图、排布线顺序、做通道和层的取舍、决定豁免与回到布局，并给出理由。**LLM 不直接输出铜皮坐标**。

**代价函数初值**（mm 等效，供 M5 布线器使用；修复器已用其中的转角与斜行部分）：主方向直行 1.0/mm，逆主方向 1.5（4 层）或 1.2（2 层），45° 斜行 1.1/mm；45° 转向 +1，90° 转向 +3，锐角与回折为无穷大；过孔 +30（2 层）或 +15（4 层，自动配回流过孔），关键网过孔为无穷大；短段 +2；2 层板底层 +2/mm；攻击网 3h 内 +0.5/mm；偏离束轴 +0.5/mm。

**EDA 对接要点**：嘉立创 EDA 专业版用 `eda.pcb_PrimitiveLine.create(net, layer, startX, startY, endX, endY, lineWidth, primitiveLock)` 写直线段，单位 mil，没有公开的推挤或交互布线接口，所以几何必须离线算好、过闸门后整批写入；mm 与 mil 换算后按 0.01 mil 取整，再过一次闸门（1 µm 容差能吸收取整）。KiCad 9 起优先用 IPC API（kicad-python，需要运行中的 KiCad 并开启 API），SWIG 版 pcbnew 在 KiCad 11 中移除；无头流程直接改 `.kicad_pcb` 再用 `kicad-cli pcb drc` 验证。FreeRouting 可作为后端（`java -jar freerouting.jar -de board.dsn -do board.ses -mp 20`），关键网先手工布好并锁定，结果必须过 `route_fix.py` 和 `lint`。

## 10. 设计哲学与常见迷思

1. **布局决定布线**：大部分布线质量问题在布局时就定了——逃逸方向、连接器朝向、去耦位置。
2. **电流走回路**：每根信号都能指出回流路径，换层时回流也跟着换。
3. **先规划通道再落线**：没有全局视图就没有整齐的局部。
4. **每个拐弯、每个过孔都要有理由**：代价函数让无理由的拐弯和过孔自然消失。
5. **相同的事用相同的方式做**：同类网络用同一种出线方式、同一个间距、同一个方向。
6. **整齐通常意味着正确，但不等于正确**：整齐度和电气约束分开评，电气约束（VF-26）一票否决。
7. **能用代码算的不让模型猜**：模型管意图，几何引擎管坐标。

迷思：

- “90° 拐角一定不行”——在本板型频段内电气影响可以忽略；统一用 45° 是为了密度、可检查性和一致性，射频线按厂商要求用 135° 或圆弧。
- “酸阱让 90° 不能用”——基本过时，但锐角楔形仍有风险，所以禁止锐角。
- “3W 是硬规则”——真正的物理量是到参考平面的高度。
- “自动布线器不能用”——FreeRouting 在真实 2 层板上的全通过率与最新学习型方法相当；问题在于缺约束和后处理，所以用“关键网手工 + 自动布其余 + 强制后处理验收”。
- “任意角度更先进”——在拓扑规划里是好的中间表示，在普通数字板上是飞线物化的坏味道。

局限：

- VF-16…27 的阈值和权重是工程经验值，需要用官方参考布局和人工精布的板子标定。
- 修复器只改几何，不改拓扑（过孔、层、连接关系）；空间不够时标 `needs_manual`，不会推挤其他网络。圆弧和 GND 网络不处理。
- 间距检查用的是中心线距离减半宽，焊盘按矩形或圆形近似；修复后仍要在 EDA 里跑 DRC。
- 地破碎度只在从 `.kicad_pcb`（铺铜已填充）或 Gerber 提取的数据包上算；直接读 plan.json 时不算。
- 角度判定容差 1 µm：KiCad 文件坐标是 4 位小数，修复器把坐标取到 0.1 µm，45° 段两轴变化量相同，不会因取整变成非八方向。
