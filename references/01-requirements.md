# 需求明确：显性需求、隐性需求与硬件形态

## 目录
1. 提问策略
2. 需求维度（用户通常会说的）
3. 隐性需求（用户通常想不到的）
4. 需求 → 硬件形态映射
5. 架构决策的顺序

## 1. 提问策略

用户通常只描述功能（"做一个戴在手腕上测动作的东西，蓝牙传到手机"）。你的任务是把它变成能决定硬件的数字，同时不把用户问烦。

- 先复述你已经理解的内容和已经能推断的结论。
- 只追问**会改变架构**的问题，一次 5–7 个以内，优先级如下：
  1. 供电方式与续航目标（电池类型/尺寸限制、要用多久、能否充电或更换）
  2. 数据：采什么、采样率、位宽、实时传还是存后传、传给谁（手机/网关/云）
  3. 尺寸、重量、佩戴或安装方式、外壳材料
  4. 使用环境（温度、防水、室内外）
  5. 产量与成本目标、时间表
  6. 是否已有指定平台或已有代码（如团队已熟悉 nRF Connect SDK）
- 其余维度用默认值并明确写成"假设"，让用户纠正比让用户回答容易。
- 用户回答"不知道"时，给出两三个典型选项和各自的后果，帮他选。

## 2. 需求维度

### 功能与感知
- 被测量是什么，量程、分辨率、噪声、带宽各是多少。采样率由信号带宽决定（步态约 50–100 Hz，振动监测可能要 kHz 级，心率 PPG 25–100 Hz）。
- 测量对象是"设备自身的运动"还是"它所附着物体的运动"，后者要求刚性耦合。
- 是否需要多设备间时间同步，精度到多少（ms 级靠无线协议时间戳，µs 级需要专门设计）。
- 是否需要本地计算（滤波、姿态解算、边缘 ML），这决定 MCU 档次和 RAM/Flash。

### 通信
- 对端是谁：手机（几乎只能 BLE / WiFi / NFC）、专用网关、直接上云。
- 应用层数据率、允许的延迟、单向还是双向、连接是常驻还是偶发。
- 距离与环境：贴身、同屋、穿墙、户外百米到千米。
- 设备数量与组网：点对点、星型、Mesh。

### 供电与续航
- 目标续航（天/月/年）以及用户能接受的充电或换电池频率。
- 电池的尺寸重量上限。
- 是否有外部电源或能量采集的可能。

### 机械与环境
- 外形尺寸、厚度、重量；外壳是塑料还是金属。
- 工作/存储温度范围；防水防尘等级；跌落、振动、汗液、紫外线。
- 安装或佩戴位置。

### 交互
- 按键、LED、蜂鸣/振动、屏幕；或者完全无界面。

### 商业
- 产量（10 台原型与 10 万台量产的选型逻辑完全不同）、BOM 成本目标、上市时间、目标市场（决定认证）。

## 3. 隐性需求（主动提出）

下面每一项都对应真实项目里"板子做完才发现"的问题。逐项过一遍，把与该项目相关的写进"你可能没考虑到的问题"。

### 电源相关
- **峰值电流**：用户只想到平均功耗，但电池的内阻决定它能否提供射频发射、Flash 擦写、电机启动时的峰值。纽扣电池在这方面是典型陷阱。
- **电池末期与低温**：电压下降、内阻上升。设备要在电池剩 20% 且 0 °C 时仍能发射，而不是只在新电池室温下工作。
- **欠压行为**：电池耗尽时是干净地关机，还是在欠压点反复重启并可能写坏 Flash。
- **运输与库存**：出厂到用户手里可能半年，需要运输模式（ship mode）或足够低的待机电流；锂电池运输需要 UN38.3 等合规。
- **充电时能否使用**：决定是否需要电源路径管理。
- **电量显示**：用户会想知道还剩多少电，电压估算与库仑计的精度和功耗不同。
- **充电安全**：锂电池的充电温度限制（通常 0–45 °C）、NTC、过充过放保护。

### 可靠性相关
- **上电与复位期间的引脚状态**：MCU 复位时 IO 为高阻，外部电路（电机、加热器、负载开关）此时不能误动作。
- **ESD**：凡是人手能碰到的金属（按键、充电触点、USB、电极）都需要保护。
- **看门狗与死机恢复**：封闭外壳、不可拆电池的设备没有"拔电重启"，需要硬件看门狗或可靠的复位手段（例如长按、插充电器复位）。
- **凝露与防水**：高阻节点（MΩ 级分压、晶体）在潮湿环境下会漏电。
- **器件自发热**：会影响温度测量和 IMU 零偏。

### 数据与固件相关
- **固件升级（OTA）**：需要双镜像空间或外部 Flash；升级时的峰值电流和断电保护。
- **离线缓存**：手机不在身边时数据存哪里、存多久，决定存储器容量和类型；擦写的峰值电流和寿命。
- **时间保持**：是否需要掉电不丢的实时时钟，精度要求（32.768 kHz 晶体 ±20 ppm 约等于每月 1 分钟内）。
- **安全**：安全启动、调试口锁定、密钥存储（片内还是安全芯片）、加密对功耗和算力的要求。
- **唯一标识与校准数据**：存哪里，产线怎么写入。

### 生产与认证相关
- **如何烧录与测试**：测试点、针床、板边连接器；产线不可能逐个接杜邦线。
- **射频认证**：FCC / CE-RED / SRRC / TELEC / Bluetooth SIG。用认证过的模组可以省下大部分费用和时间，芯片直贴(chip-down)则要自己做全套；改天线可能使模组认证失效。
- **供应与生命周期**：关键器件是否有替代料、是否长期供货、交期。
- **传感器校准**：IMU 零偏、磁力计硬铁/软铁校准、温度补偿是否要在产线完成。
- **医疗/穿戴**：接触皮肤的材料生物相容性、漏电流限制；若为医疗用途有额外法规。

### 结构与射频相关
- **外壳与人体对天线的影响**：金属外壳、电池、手握、贴身佩戴都会使天线失谐或衰减，天线必须在最终外壳和佩戴状态下调试。
- **传感器位置约束**：见 `03-sensor-placement.md`，它们会反过来决定板形。
- **装配**：电池如何固定和连接、FPC 弯折区、按键与壳体的配合公差。

## 4. 需求 → 硬件形态映射

| 需求特征 | 对应的硬件形态 | 需要注意 |
|---|---|---|
| 续航以年计，数据很少（每分钟到每小时几十字节） | 一次电池（CR2032、锂亚 Li-SOCl2、AA 碱性/锂铁）+ BLE 广播 / LoRa / Thread 休眠终端；尽量少的稳压级 | 峰值电流需要储能电容；自放电与电池保质期 |
| 续航以天/周计，连续采样并传输 | 可充锂电池 + 充电芯片 + 高轻载效率的降压；BLE 连接 | 充电接口、保护、电量计、温度 |
| 连接手机 | BLE（首选），大数据量时 BLE + WiFi 或经典蓝牙 | iOS/Android 对连接参数的限制 |
| 直接上云、有市电或大电池 | WiFi（ESP32 系、nRF70 系等）或蜂窝 | 峰值电流数百 mA，电源设计按此做 |
| 广域、无网关基础设施 | NB-IoT / LTE-M / LoRaWAN | SIM、天线尺寸、运营商覆盖、峰值电流 |
| 高采样率原始数据（音频、kHz 级振动、多通道生理信号） | 本地压缩或特征提取 + BLE 2M PHY；或本地存储 + 批量上传；或 WiFi | 先算数据率，见 `02-wireless-selection.md` |
| 测整体的平动加速度且物体会转动 | IMU 靠近转动中心，或已知杆臂做补偿 | 见 `03-sensor-placement.md` |
| 只测姿态/角速度/手势/计步 | IMU 位置自由度大，重点是刚性安装、远离应力与热 | 同上 |
| 极小体积 | SiP / WLCSP 封装、高密度互连(HDI)、软硬结合板、芯片天线 | 成本和板厂能力上升；天线效率下降 |
| 金属外壳 | 天线开窗、外置天线、或利用壳体做天线 | 必须早期与结构协同 |
| 防水 | 无线充电或磁吸触点、气压计/麦克风用防水透气膜、无开孔按键 | 触点腐蚀与 ESD |
| 需要 OTA | 片内 Flash ≥ 2 倍固件或外置 SPI NOR | 外置 Flash 的深度掉电电流 |
| 长期离线记录 | SPI NOR / NAND / SD 卡 | SD 卡待机电流和峰值电流大，通常要断电控制 |
| 小批量、赶时间 | 认证模组 + 参考设计 | 成本和尺寸让步 |
| 大批量、成本敏感 | 芯片直贴 + 自做认证 | 射频设计与测试能力 |

## 5. 架构决策的顺序

这个顺序避免了后面的决定推翻前面的：

1. **数据率与通信对象** → 无线方案。
2. **无线方案的峰值电流 + 续航目标 + 尺寸** → 电池化学体系与容量。
3. **电池电压范围 + 各器件电压要求** → 电源树（直驱 / LDO / 降压 / 升降压）。
4. **算力、外设、无线** → 主控 SoC 或 MCU + 射频组合，模组还是芯片直贴。
5. **传感器与放置约束、天线、连接器、电池** → 板形与层数。
6. **功耗预算闭合检查** → 不闭合则回到第 1 步调整占空比、数据率或电池。
