# 设计确认闸门：布局布线前的强制确认流程

本 skill 不是一键出板工具。它服务于愿意把设计想清楚、说清楚、并逐步检查结果的人。
**没有拿到规范性设计所需的全部信息和优先级，并且没有经过用户逐级确认，就不摆放器件、不布线、不宣布完成。**
这一条没有例外：用户催促、用户不在场、任务被设成隔夜自动运行，都不能跳过。

## 1. 为什么强制：一次真实的误用

某使用者把原理图导入 PCB、随手摆好器件后，在一个 AI 代理里给了一句目标“把板子布完”，让它跑了一整晚。第二天代理报告“完成”。板子 DRC 是干净的，但无法使用：走线是任意角度的斜线和长距离绕行，信号随意换层，关键区域（射频、晶振、电源）与一般信号搅在一起。

复盘下来，问题不在“模型不够强”，而在流程上缺了五样东西：

| 缺了什么 | 后果 | 哪道闸门本应拦住 |
|---|---|---|
| 没有给外壳、板框、接口位置 | 器件位置没有依据，后面所有走线都建立在随意的布局上 | G1 |
| 没有功能分区，没人看过布局截图 | 布局错了，布线救不回来；电源、射频、数字混在一起 | G2、G3 |
| 没有布线优先级和网络类约束 | 关键网和一般信号被同等对待，晶振、开关回路被绕长 | G4 |
| 目标设成“DRC 通过 / 全部连通” | 这个指标可以被满足而不代表质量：任意角度、长绕线、乱打孔都不违反 DRC | 规则 3.4 |
| 中途没人检查，结论由 AI 自己宣布 | 错误一路累积到最后 | 规则 3.5、G5 |

另外两点也值得注意：使用者不知道 skill 里有交互式布局，也不清楚效果；README 的使用示例都是一句话，客观上鼓励了“一句话做完”的用法。所以本次同时改了 README，并把闸门写进工具，而不是只写在文档里。

## 2. 六道闸门：每一级必须拿到什么

闸门内容记在项目目录的 `design-brief.json`（`python scripts/design_gate.py init` 生成模板）。“待填”“待定”“你定”“随便”“不知道”一律视为没填。

| 闸门 | 内容 | 必须拿到的信息 | 放行后可以做 |
|---|---|---|---|
| **G0 需求与工艺** | 这块板做什么 | 功能与使用场景（一句完整的话以上）、供电方式与峰值电流、无线方式（没有写“无”）、使用环境、层数、板厚、板厂 | 原理图评审、选型 |
| **G1 机械约束** | 板子长什么样、什么东西的位置已经被外壳定死 | 板框尺寸或外壳导出的 DXF、外壳材料与限高、固定孔（没有写“无”）、**每个固定件**（接口、按键、灯、天线、电池、传感器开窗）贴哪条边、沿边位置与容差、禁布区（没有写“无”） | **开始摆放器件** |
| **G2 功能分区** | 每个功能块放在哪 | 至少两个功能块，每块的器件位号、区域（左 / 右 / 上 / 下 / 角 / 三分之一，或板框比例坐标）、理由；电源与信号流向；**用户看过并认可的布局截图** | 布局检查 |
| **G3 布局检查** | 摆放有没有问题 | `layout_lint.py --brief` 的 JSON 报告，无 P0，且基于当前的 G0–G2；用户同意保留的 P1/P2 及理由（没有写“无”） | 布线规划 |
| **G4 布线规划** | 怎么布、先布什么、什么算合格 | 每层用途（层数要对上）；布线优先级表（档位、网络、每个网络的作用、手工还是工具辅助、规则），**逐档确认**；差分对（没有写“无”）；电源网络与电流；验收分数（route_lint ≥ 75，建议 ≥ 80） | **开始布线**：手工布线、工具辅助布线、`route_fix.py`、`route_lint.py gate`、扩展写回 |
| **G5 交付验收** | 布完了吗 | `route_lint.py lint --json` 报告达到验收分数且无 P0；EDA 原生 DRC 错误数为 0；用户看过的布线截图 | **宣布完成、交付打样** |

每一级都建立在前一级上：前面的内容一改，后面的确认自动失效，必须重新确认。

## 3. AI 必须遵守的规则

**3.1 一句话请求不动手。** 用户说“帮我布线”“自动布完”“一键完成”“做完它”而闸门未放行时，先运行 `python scripts/design_gate.py status design-brief.json`（没有文件就先 `init`），然后：
- 用一两句话说明为什么要先确认（布局错了布线救不回来；DRC 通过不代表能用）；
- 按 G0 → G1 → … 的顺序，一次问一级缺的信息，每次不超过 5–7 个问题；能从原理图、板文件、外壳图读出来的先读出来，写成“我读到的是……，对吗？”请用户核对，不要让用户重复已经给过的东西；
- 可以先做只读工作作为提问依据：读原理图、读板子、跑 `layout_lint.py` 和 `route_lint.py lint`、指出看得见的问题。

**3.2 不替用户编。** 不得把“待填”改成自己猜的值。用户说“你定”“随便”时，给出 2–3 个候选方案，各自写清取舍（例如“USB 放左边：线最短，但要和外壳开孔对齐；放下边：……”），用户选了才写入。器件手册能给出的数值（天线净空、去耦距离）从手册取，并注明出处。

**3.3 只有用户能确认。** 把 `summary` 的输出原样发给用户，等用户回复包含确认码的原话，再用 `--quote` 记下。不得自己确认，不得把用户早先的“好的”“继续”当作确认，不得在用户没回复时进入下一级。

**3.4 不以“DRC 为零”作为目标或停止条件。** 完成的定义是 G5 放行：route_lint 达到 G4 写下的验收分数、无 P0、原生 DRC 为零、用户看过布线截图。全部连通且 DRC 为零只是 G5 的一个必要条件。

**3.5 无人值守时只做到下一道闸门。** 任务被设成隔夜运行、定时运行，或用户不在场时，做完当前已放行阶段的工作后停下，把下一级的摘要和确认码、截图、检查报告整理好留给用户。不允许“先布了再说”。

**3.6 按功能块推进，每块都给人看。** 布线按 G4 的档位、按 `18-routing-philosophy.md` 的方法一块一块布；关键档（射频、晶振、开关回路、高速差分、模拟）手工布，只有 G4 里标为“工具辅助”的档位才能用自动布线器；每完成一块，截图并附 `route_lint.py lint` 结果发给用户。

**3.7 措辞。** G5 放行之前，不说“完成了”“布好了”。只说进展到哪一级、还差什么、需要用户确认什么。

**3.8 偏离要回头。** 布线中发现布局放不下、分区要改、优先级要调，回到对应闸门修改并重新确认，不要在布线阶段悄悄挪器件。

## 4. 怎么确认：确认码

```bash
python scripts/design_gate.py summary design-brief.json G1
```

输出该闸门的全部内容和确认码，例如 `G1-4c09ae`。确认码由这一级和前面所有级的内容算出（SHA-256 前 6 位）：内容改了，码就变了，旧的确认作废。

用户核对后回复“确认 G1-4c09ae”，AI 记下原话：

```bash
python scripts/design_gate.py confirm design-brief.json G1 --quote "确认 G1-4c09ae"
```

用户在终端里也可以亲手确认：`python scripts/design_gate.py confirm design-brief.json G1 --tty`。

在嘉立创 EDA 扩展里，确认只能在“设计确认”面板中由用户手动输入确认码完成；通过本地 MCP 桥接入的 AI 代理可以读取和填写设计确认内容，但**不能确认**。

说明：命令行的 `--quote` 依赖 AI 如实转述用户原话，工具无法防止蓄意伪造；它防的是误操作和“顺手就做了”。扩展面板里的确认是真正只有人能完成的一步。

## 5. 工具里的强制点

| 工具 | 需要 | 未满足时 |
|---|---|---|
| `design_gate.py require --stage place` | G0、G1 | 退出码 3，列出缺什么 |
| `design_gate.py require --stage route` | G0–G4 | 退出码 3 |
| `design_gate.py require --stage deliver` | G0–G5 | 退出码 3 |
| `route_fix.py … --brief` | route | 拒绝修改走线，退出码 3 |
| `route_lint.py gate … --brief` | route | 拒绝放行写入 EDA 的走线计划，退出码 3 |
| 通过 EDA MCP 写走线（`10-easyeda-execution.md`） | route | 写入前先跑 `require --stage route`，不通过不写 |
| 扩展：写回修复、MCP `routing_fix_apply`、`routing_gate` | G0–G4 已在面板确认 | 拒绝并提示打开“设计确认” |
| 扩展：MCP `design_brief_confirm` | — | 不存在：确认只能在面板里做 |
| 扩展：布线优先级逐档确认 | 前一档已确认 | 只接受面板里的点击；AI 代理调用会被拒绝 |

只读的检查（`route_lint.py lint`、`order`、`layout_lint.py`、扩展的检查与动画）不受闸门限制，但没有设计确认文件时，报告顶部会说明哪些检查没做。

## 6. `design-brief.json` 字段说明

模板见 `python scripts/design_gate.py init`，完整示例见 `tests/fixtures/brief-principles.json`。要点：

- `roles`（可选）：`{"U1": "mcu", "U3": "dcdc", "ANT1": "antenna"}`，覆盖按位号推断的角色。角色用于天线、电感、晶振、电池、连接器之间的间距检查。
- `G1_mechanical.fixed[]`：`{ref, what, edge, along_mm, tol_mm, side, reason}`。`edge` 取 `left / right / top / bottom / inner`，按 EDA 画面方向；`along_mm` 是器件中心沿该边的位置，上下边从左端量、左右边从下端量；`tol_mm` 默认 1。
- `G1_mechanical.keepouts[]`：`{rect_frac: [fx0, fy0, fx1, fy1], reason}`（板框比例，原点左下）或 `{rect_mm: [x0, y0, x1, y1], reason}`（板文件坐标）。
- `G2_partition.blocks[]`：`{name, parts: [...], region, why}`。`region` 可写 `left`、`right`、`top`、`bottom`、`top-left`、`top-right`、`bottom-left`、`bottom-right`、`center`、`left-third`、`middle-third`、`right-third`、`top-third`、`bottom-third`，或比例矩形。天线的匹配网络放进天线所在的块，就不会被当成占用净空区。
- `G3_layout_check.report`：`layout_lint.py 板子 --brief design-brief.json --json layout-lint.json` 的输出。报告里记着 G0–G2 的哈希，分区一改就要重新跑。
- `G4_routing_plan.priorities[]`：`{tier, name, classes, nets, notes: {网络: 作用}, why, method, rules}`。`method` 写“手工”“工具辅助”或“铺铜”。档位顺序参照 `17-routing-principles.md`：射频 → 晶振 → 开关回路与高压 → 高速差分 → 时钟 → 模拟 → 电源 → 一般信号 → 地。`design_gate.py priorities --board 板子 --write`（或扩展的“从板子梳理”）按网络名、连接的器件（位号与型号推断角色）和网络类生成草稿，AI 再结合板子功能修正。
- **逐档确认**：第 n 档的确认码 `T<档位>-xxxxxx` 由第 1…n 档的内容和 G0–G3 的哈希算出，必须先确认前一档；所有档位确认后 G4 才算信息齐全，再整体确认 G4。挪动网络或改走法，从这一档往后的确认自动失效。记录在 `confirmations.tiers`。
- `G5_acceptance`：`route_report`（`route_lint.py lint 板子 --json route-lint.json`）、`drc_errors`（数字）、`screenshots`（文件名列表）。

### 布局检查器 `layout_lint.py` 的规则

| 规则 | 级别 | 内容 |
|---|---|---|
| LAY-01 | P0 | 器件超出板框（连接器、天线允许伸出） |
| LAY-02 | P0 | 同面器件焊盘区域重叠 |
| LAY-03 | P0 / P1 | 固定件不在指定的边（P0）；沿边位置超出容差（P1） |
| LAY-04 | P1 | 功能块的器件不在该块的区域内 |
| LAY-05 | P2 | 两个功能块的主器件区域交叠超过 30% |
| LAY-06 | P1 | 天线不在板边；天线 3 mm 净空区内有其他功能块的器件 |
| LAY-07 | P1 / P2 | 天线与电池 / 连接器 ≥ 5 mm，电感与天线 ≥ 8 mm，电感与晶振 ≥ 4 mm，晶振与天线 ≥ 4 mm |
| LAY-08 | P0 | 器件进入禁布区 |
| LAY-09 | P2 | 主器件（IC、连接器、晶振、电感、天线、电池、按键）没有分到任何功能块 |
| LAY-10 | P1 | 设计确认里写的位号在板上找不到 |
| LAY-11 | P2 | IMU 离板边 < 3 mm，或离连接器、按键、固定孔 < 5 mm（应力） |
| LAY-12 | P2 | 温湿度 < 8 mm、IMU < 5 mm、晶振 < 4 mm、电池 < 5 mm 靠近 DCDC / LDO / 充电芯片（热） |
| LAY-13 | P1 | 磁力计离电感、电池、磁性器件 < 10 mm |
| LAY-14 | P2 | 功率电感离 IMU、温湿度、麦克风、气压计 < 4 mm |
| LAY-15 | P3 | 电源流向绕路：稳压器离主控比充电芯片还远 |
| RTP-01…08 | 同 `17-routing-principles.md` | 就近原则：去耦、晶振负载电容、ESD、串阻、地过孔；未布线时按焊盘直线距离估计 |

嘉立创 EDA 自带的 DRC 管连通性、间距、线宽、过孔、差分对和元件间距（装配干涉）；上表这些“该不该放这里”的检查它不做，这正是本检查器和扩展“布局”页的用途。

## 7. 给用户：怎样用好这个 skill

开始前请准备好，并在第一条消息里尽量说清：

1. **这块板做什么**：功能、使用场景、供电、无线、环境。
2. **外壳和板框**：外形尺寸或外壳图纸（DXF / STEP / 带尺寸的截图），限高，固定孔。
3. **位置已经定死的器件**：USB 在哪条边、离哪个角多远，按键、灯、天线朝哪、电池放哪。
4. **你希望的功能分区**：哪一块放哪里、为什么。没想好可以让 AI 给两三个方案，但要由你来选。
5. **关键信号和优先级**：哪些是射频、晶振、开关电源、差分、模拟；你最在意什么。
6. **检查的节奏**：每一级 AI 会发摘要和确认码，请认真核对后再回复确认；布线过程中每完成一块会发截图，请看了再让它继续。

一个合格的开场示例：

> 做一个腕戴动作记录器，CR2032 供电、BLE 连手机、室内外 -10–45 °C。外壳是 38 × 30 mm 圆角矩形（DXF 附上），顶面限高 2.5 mm、底面贴电池。USB-C 只用来烧录，放下边中间；按键在右边离上角 8 mm；天线朝上边，上边 6 mm 内不放金属。分区想法：天线和 nRF52 在上半部、电源和充电在左下、IMU 在中间靠下。先按你的流程逐级确认，再开始摆放。

不合格的开场示例：“帮我把这块板布完。”——收到这样的请求，AI 会先按本文件逐级提问，不会直接动手。
